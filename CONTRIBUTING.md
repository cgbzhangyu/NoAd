# Contributing

Every rule change must include:

- A stable rule ID and a narrowly scoped purpose.
- Public evidence with URL, license and whether material is derived or evidence-only.
- Risk level, MITM host list when applicable, and critical-flow impact analysis.
- Static tests and sanitized match examples.
- A device verification record before promotion to stable.

Do not submit secrets, full URLs with query parameters, bodies, HAR files,
third-party scripts without license review, or rules that force user traffic to
DIRECT/PROXY.
